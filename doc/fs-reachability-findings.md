## Main finding

The full **483-prime real L-P target is in the subgroup generated by the
actual vectors**. A direct integer-coefficient witness is checked both in
every original component and in the original multiplicative residues:

```text
product(p_i ** c_i) =  1 mod Lambda_minus
product(p_i ** c_i) = -1 mod Lambda_plus
```

The reported coefficients are not all zero or one. This does **not** solve
the squarefree subset problem, nor does it prove that a Boolean witness does
not exist. Membership means that no separating group character can rule out
this particular full-pool target; combinatorial obstacles may remain.

Membership here is not vacuous. In the binary quotient `G / 2G`, the
483 generators have rank **393 in 394 coordinates**, a codimension-one
deficit; all **97 odd prime-field quotients** have full row rank. The
generated subgroup is therefore proper, with **index at least two**.
There is a nontrivial order-two character annihilating every generator,
and the real target lies in its kernel. The positive result thus passes a
genuine necessary constraint. The prime-field ranks alone do not determine
the exact full prime-power subgroup index or establish Boolean feasibility.

The four smaller real-target cases remain nonmembers with directly verified
character certificates. All five planted-control cases are members, as
expected. Their integer certificates do not recover the hidden Boolean
subsets and must not be counted as successes of Track A's control-recovery
task.

## Method: primary rings, not independent bit slices

### 1. Embed each primary system faithfully

For a fixed prime `ell`, write the relevant component orders as
`ell ** a_j`, and set `M = ell ** max(a_j)`. An equation

```text
sum_i A[j,i] * c_i = t[j] mod ell**a_j
```

is equivalent to

```text
(M / ell**a_j) * sum_i A[j,i] * c_i
    = (M / ell**a_j) * t[j] mod M.
```

This retains all prime-power information. It does not replace carries by
independent GF(ell) equations or require the coefficients to be Boolean.

### 2. Use minimum-valuation pivots

At each elimination step, choose a nonzero entry with smallest
`gcd(entry, M)` in the remaining submatrix. That gcd is a power of `ell`
and divides every remaining entry.

Row swaps and multiplication by units are invertible. Column swaps only
relabel variables. Normalize the pivot to `ell ** v`, then subtract exact
multiples of its row to clear the column below it. Record the row operations
for possible certificate recovery.

If the transformed right side is not divisible by the pivot divisor, the
equation is inconsistent. If elimination leaves a zero row with nonzero
right side, it is also inconsistent.

Otherwise triangular back-substitution works: every later coefficient in a
pivot row is divisible by that pivot divisor, so choosing the later
variables first preserves the required divisibility. Set remaining free
variables to zero and return one exact primary coefficient vector.

### 3. Recover a negative certificate

Reverse the recorded row operations on the offending row functional.
Undo the initial row weights when expressing the functional in the original
coordinates.

The certificate has modulus `d` and terms `(j, b_j)` satisfying:

```text
b_j * m_j = 0 mod d                  for every term
sum_j b_j * v_i[j] = 0 mod d         for every pool generator i
sum_j b_j * t[j] != 0 mod d          for the target.
```

The first condition is essential: the character must be well-defined on
the original group. A common divisor of all coefficients and the modulus
is removed before publication. Consequently a character recovered in a
larger primary ring is not misleadingly presented as a genuinely
higher-order obstruction if it reduces to modulus two.

The checker verifies these conditions directly using the original vectors
and the existing independent `verify_obstruction` helper. It does not replay
or trust elimination.

### 4. Recombine positive witnesses by CRT

The primary coefficient vectors may differ between primes. Their moduli
are coprime, so CRT gives a single integer coefficient for each generator
that satisfies every primary equation simultaneously.

Coefficients are represented canonically modulo the exponent of `G`,
`lcm(m_j)`. The checker recomputes each original group equation directly.
For actual-prime instances it also evaluates modular powers of the original
primes on both LCM sides.

No candidate `n` with repeated factors is declared. If a returned witness
happens to be Boolean, odd and of size at least three, and attains the real
L-P target, it must additionally pass the existing independent counterexample
verifier, including the direct polynomial congruence. None did here.

## Why full prime powers matter

Consider:

```text
G = Z/4 x Z/4
generators = {(1,1)}
target = (0,2).
```

Coordinate checks pass, and the target reduces to zero modulo two. Yet the
generated subgroup is diagonal, so the target is absent. The character
`a-b mod4` proves nonmembership.

Conversely, in `Z/2 x Z/4`, the generator `(1,1)` does reach `(0,2)` by
coefficient two. Correctly scaling different row moduli is needed to avoid
rejecting that valid integer witness.

These are regression fixtures, not claims about the actual pilot. In the
pilot, the smaller real targets were already rejected by prime-field
checks; full-power membership confirms those outcomes. The new substantive
positive result concerns the full 483-prime target.

For the full medium instance:

- Group size remains approximately **3,951.73 bits**.
- Its exponent has **781 bits**; this is the coefficient modulus, not the
  group order or a size bound on a squarefree counterexample.
- There are **98** primary systems.
- The published real-target witness has 262 nonzero and 221 zero integer
  coefficients. The nonzero coefficients are not restricted to one.
- Both full-instance membership computations completed within the stated
  budgets; their representation estimate was approximately 45 MiB.

Separately, the [exact product-size bound](fs-controls-findings.md) for this
real fixed-LCM target gives `P_91 < Lambda_minus + 1 <= P_92`, where `P_k`
is the product of the `k` largest eligible primes. With odd cardinality,
this requires **at least 93 distinct-prime, zero-or-one factors**. That
bound applies to Boolean subset products, not to unrestricted integer
coefficients: neither the witness's 483 entries nor its 262 nonzero
coefficients represent a selected-prime cardinality. The membership
certificate gives no evidence that the Boolean size floor can be attained,
or that any larger eligible subset exists. Conversely, the Boolean size
bound does not constrain or invalidate the integer-coefficient certificate.

The pivot summaries are algorithm diagnostics, not independently certified
normal forms or subgroup-order calculations. The independently certified
conclusions are membership/nonmembership via the direct witnesses.

## Budgets and interpretation of performance

Defaults per membership computation:

| Limit | Value |
|---|---:|
| Wall time | 60 seconds |
| Charged work units | 200,000,000 |
| Input and working matrix cells | 1,000,000 |
| Workspace representation estimate | 512 MiB |
| Scalar bit length | 4,096 |

Work units charge scanned/updated scalar entries and recorded-operation
recovery, not CPU instructions. The cell limit is explicit; the workspace
number is a conservative representation estimate, **not an OS-enforced RSS
cap or a measurement of whole-process peak memory**.

Resource-limit stops return `unresolved` with a reason and no proof.
Invalid input and internal invariant failures are explicit errors, not
success-shaped fallback results.

Reported membership timing excludes loading and independently verifying the
frozen dataset and excludes final certificate verification. Those operations
can cost appreciable time and must be included when comparing total workflows.
Timings are observations, not portable complexity or production estimates.

- Exhausted all 256 ordered two-generator systems in `C4 x C4`, checking
  every one of the 16 targets: **4,096 decisions** against an independent
  breadth-first subgroup oracle.
- Checked **1,752** additional target decisions across seeded small mixed
  groups, including heterogeneous powers and different primes.
- Tested empty and duplicate generators, noncanonical residues, divisible
  nonunit pivots, row/variable permutations, full CRT coefficient recovery,
  and an obstruction in a later primary system.
- Adversarial tests reject falsified coefficients, invalid characters,
  changed input/source hashes, misclassified targets, and Boolean-feasibility
  claims substituted for the recorded integer-membership scope.
- Resource tests check time, work, cells, estimated workspace and scalar
  caps, including stopping after primary solves without leaking a partial
  witness.
- Standalone verification is tested with the membership and elimination
  functions replaced by exceptions, proving that checking a saved result
  does not invoke either algorithm.
- The original 65-test pilot suite remains part of the combined regression
  run. **All 91 tests pass on Python 3.9.13 and 3.14.5.** All prior artifacts
  remain unchanged.
- The saved report passes standalone mathematical verification on both
  runtimes: **10 cases, 6 members, 4 nonmembers, no unresolved cases and
  no counterexamples**. The session-local embedded Python 3.9 runtime needs
